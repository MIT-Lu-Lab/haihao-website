# Local development

This is an English-language Astro static-site prototype. Home and Publications are the initial design samples; the other navigation destinations provide starter content. Value is reserved for content from Haihao.

## Run locally

Use Node 24 LTS (see `.nvmrc`).

Tests and research generators import TypeScript directly using Node's native
type stripping. Node 22 requires version 22.18 or later; Node 24 is recommended.

Install dependencies and start the development server:

```sh
npm ci
npm run dev
```

Open the local URL printed by Astro, usually http://localhost:4321.

```sh
npm test
npm run check
npm run build
npm run preview
```

The static build is generated in `dist/`. Hosting and a production domain have not been configured. The current paths assume deployment at the domain root.

## Research figures

Run `npm run research:generate` to regenerate the PDHG comparison and online allocation data. The command runs `scripts/pdhg-study.mjs` before `scripts/pdhg-comparison.mjs`, which reads the first script's output, then runs `scripts/online-allocation.mjs`. Paths resolve relative to the scripts, and the generators create their output directories as needed.

- `data/research/`: reproducible research artifacts (JSON and CSV files); imported data is bundled into the page, while the source directory is not copied to the site.
- `public/pdhg-comparison.json`: the comparison data fetched by the research page.
- `src/components/TheoryFigure.astro`: canvas markup, text alternative, legend, and styles.
- `src/lib/research/`: playback, drawing, and interpolation modules bundled through the component's Astro script.
- `src/components/PropertyFigure.astro`: property valuation curves and metrics,
  with playback in `src/lib/research/property-animation.ts`.
- `data/research/property-profiles.json`: measured profiles extracted from the
  supplied manuscript, with source and extraction details. This snapshot is
  not regenerated by `research:generate`.

The GPU composition lives in `src/components/GpuFigure.astro`. Image sources and attribution are maintained in `data/research/image-sources.json`.
To regenerate the matrix image, download the archive linked in
`data/research/rail4284-figure.json`, then run:

```sh
python scripts/generate-lp-structure.py /path/to/rail4284.tar.gz
```

This script requires Python 3.11 or later, NumPy, and Pillow (`python3` may be
needed outside Windows). It writes `public/images/research/rail4284-density.png`
and `data/research/rail4284-figure.json`; it does not modify image attribution.
The matrix PNG uses a 128-color palette without dithering; this only quantizes
display colors, not matrix counts. Research photos and the GPU illustration
live in `src/assets/research`. Astro emits WebP at quality 80, with two widths
for the railway photo (640 and 1280), commerce photo (640 and 1120), and GPU
illustration (400 and 800). The property photo uses a single 1200px image.
Sources, licenses, and encoding details are in `data/research/image-sources.json`.

`GpuMatrixAnimation.astro` supplies the matrix SVG; the parent GPU component
initializes `src/lib/research/gpu-matrix-animation.ts` with the saved products.
Playback stops offscreen, in hidden tabs, and under reduced motion. For multiple
figures on a page, pass distinct stable `id` props to `GpuFigure` so its SVG
mask and gradient identifiers remain unique.

Generate the product samples with Python 3.11+, NumPy, and SciPy:

```sh
python scripts/generate-gpu-products.py /path/to/rail4284.tar.gz
```

The optional second argument overrides `data/research/rail4284-products.json`.
The displayed vectors aggregate contiguous entries by RMS; the y input includes
a seeded perturbation, and its transpose product is recomputed. These samples
illustrate matrix operations, not a continuous solver trajectory or benchmark.

`npm test` includes the research interpolation and playback tests, plus an independent exact-arithmetic audit. The audit requires Python 3, available as `python` on Windows or `python3` elsewhere. `src/data/` holds site content; `data/research/` holds generated research artifacts.

Research modules use TypeScript and are checked by `npm run check`.
Entry points follow `initialize<Figure>(root, data, browser)` and return
playback cleanup. Property serializes its build-time SVG coordinates, metrics,
focus and nominal penalties in one `data-property` attribute; its component
script parses that data before initialization. `playback.ts` owns the millisecond clock, visibility, reduced
motion, and listener cleanup; `easing.ts` preserves the cubic and quintic curves.
Theory playback caps frame advances at 80 ms; online playback runs at 0.8 speed.
GPU playback uses the uncapped clock. Figure tests share
`test/helpers/fake-browser.js`, with DOM and canvas stubs kept per figure.

Data loading stays outside playback: the theory figure fetches its larger
public dataset through `loadTheoryFigure`, while GPU and online figures import
saved data at build time. Figures initialize playback only after data is
available. Do not add size thresholds or data fetching to the controller.

Each figure initializes separately. Theory's `descriptionId` defaults to
`comparison-description`; pass distinct stable IDs for multiple instances.

The online bidding composition lives in `OnlineFigure.astro`; its SVG and
responsive diagram styles live in `OnlineDiagram.astro`. Playback lives in
`src/lib/research/online-figure.ts`. Run `npm run research:generate` (or `node scripts/online-allocation.mjs` alone)
to regenerate `data/research/online-allocation.json`. Shared display dimensions live in `src/lib/research/online-layout.ts`.
The component imports this data at build time; its TypeScript playback is checked by `astro check`.
The animation retains the first 23 auctions as history and plays from auction
24 through the last gain, retaining the full 48-auction axis. Playback stops offscreen, in hidden tabs, and with reduced
motion. Supply distinct stable `id` props when using multiple instances on one
page.

## Formatting

Format only the files changed for a task; keep unrelated formatting out of functional changes. Pass explicit file paths to these commands:

```sh
npm run format -- src/components/TheoryFigure.astro src/lib/research/theory-figure.ts
npm run format:check -- src/components/TheoryFigure.astro src/lib/research/theory-figure.ts
```

Generated JSON is excluded by `.prettierignore`; the hand-maintained image
attribution file remains checked. Regenerate data with its scripts instead
of formatting it manually.

The repository has not undergone a full Prettier migration, so a repository-wide format check is not a CI requirement. Prettier uses `.prettierrc.json` and the Astro plugin.

## Adding a publication

Paste the paper's BibTeX entry into `src/data/publications.bib`. Publishers,
arXiv and Google Scholar all export it, so the entry rarely needs to be typed by
hand. Nothing else needs to change: the links, the year grouping and the author
formatting are all derived at build time.

```bibtex
@article{lu2027example,
  title         = {A Paper Title, Capitalised Exactly As It Should Appear},
  author        = {Lu, Haihao and Jinwen Yang},
  journal       = {Mathematical Programming},
  year          = {2027},
  doi           = {10.1007/xxxxx},
  eprint        = {2701.12345},
  archiveprefix = {arXiv},
}
```

The entry type sets how the paper is presented:

| Entry type       | Venue field | Shown as             |
| ---------------- | ----------- | -------------------- |
| `@article`       | `journal`   | the journal name     |
| `@inproceedings` | `booktitle` | the proceedings name |
| `@unpublished`   | none        | "Under review"       |

Links are built from the fields, so record identifiers rather than URLs:

| Field                                     | Becomes          | Note                                      |
| ----------------------------------------- | ---------------- | ----------------------------------------- |
| `doi`                                     | "Paper"          | bare DOI, not a `doi.org` URL             |
| `url`                                     | "Paper"          | only for venues with no DOI, such as PMLR |
| `eprint` + `archiveprefix = {arXiv}`      | "arXiv"          | bare id, e.g. `2409.14715`                |
| `code`                                    | "Code"           | repository URL                            |
| `supplement`, `ssrn`, `conference`, `pdf` | their own labels | one-off extras                            |

Titles appear exactly as written, so capitalise them the way they should read.
Haihao's name is detected and emphasised automatically. Run `npm test` after
editing; it checks the file still parses and that the derived links are right.

## Content and design

- `src/data/site.ts`: navigation, email, Google Scholar and official CV URL.
- `src/data/publications.bib`: every publication, in BibTeX. This is the only file to edit when the publication list changes; see "Adding a publication" below.
- `src/data/bibtex.ts`: turns that BibTeX into the data the pages render. Covered by `npm test`.
- `src/data/people.ts`: all migrated students and postdocs, grouped by current/alumni status and training category.
- `src/data/software.ts`: the repositories listed on the Software page, each with a name, a one-line description and a GitHub URL.
- `src/pages/index.astro`: homepage biography, research summaries, selected honors.
- `src/pages/value.astro`: placeholder for Haihao's text.
- `src/pages/research.astro`, `people.astro`, `software.astro`, `teaching.astro`: secondary pages. Each research section pairs text with a figure on desktop and stacks them on mobile; Software lays its repositories out in a two-column grid.
- `src/styles/global.css`: shared typography, colors and responsive layouts.
- `docs/DESIGN-GUIDE.md`: the shared text roles, font sizes, spacing, and design references.
- `public/images/haihao-lu.webp`: official MIT portrait, served locally.

Publication search runs in the browser; the complete list and year navigation also work with JavaScript disabled. The mobile menu uses native HTML details/summary.

See `CONTENT-SOURCES.md` for source information and remaining editorial work. The original README guidance has been preserved.
